# Frozen proposals inside Figaro graphs

## Overview: when to enable this

`GraphProposalImportance` connects a caller-supplied joint proposal to ordinary
Figaro observations, conditions and hierarchical nodes. It is opt-in: existing
`Importance`, `ParImportance` and MCMC behavior does not change. Use it when prior
importance wastes draws away from the posterior and you can specify a useful
proposal for an explicit block of continuous variables. Start with ordinary
importance when the prior already works well or the model cannot expose such a block.

The runner creates and clears a private Universe, draws the block from the frozen
proposal, and applies the **original joint prior / full proposal** correction.
Remaining stochastic nodes are generated by the existing likelihood weighter.
For root `x`, other latent variables `z` and evidence `y`, the target is
`p(x) p(z | x) L(y | x,z)` and the sampling law is `q(x) p(z | x)`;
the weight is `p(x) / q(x) * L(y | x,z)`, including additional graph constraints.
All densities must use the same base measure/coordinates. The proposal must cover
the target support. Normalizing the prior is unnecessary for posterior means;
the proposal must be normalized and evaluable.

This is not an adapter that rewrites an existing Universe. You build a fresh graph
around the supplied root. It does not discover coordinates, automatically fit a
proposal, remove unvisited modes, or change stopping rules.

## Quick start in three steps

1. Choose the original joint prior and a frozen proposal. Here a Normal prior and
   observation `y=1` with variance `0.25` imply posterior mean `0.8` and variance `0.2`.
   The proposal deliberately uses a slightly larger variance, `0.3`.
2. Build the graph in the callback, mapping coordinates out of the supplied root.
3. Read the detached estimate, health and work counters; the graph is already cleared.

```scala
import com.cra.figaro.algorithm.sampling.{GraphProposalImportance as P, VectorImportance as V}
import com.cra.figaro.library.atomic.continuous.{Normal, MultivariateGaussianDistribution as G}
import com.cra.figaro.language.*

val prior = G(Vector(0.0), Vector(Vector(1.0)))
val proposal = V.Gaussian(G(Vector(.8), Vector(Vector(.3))))
val result = P.run(P.Config(seed = 43), proposal, prior.logDensity) { (u, root) =>
  val theta = root.map(_.head)(using "theta", u)
  Normal(theta, .25)(using "measurement", u).observe(1.0)
  theta
}
println(result.health.diagnostics.mean) // about 0.8; Option, not a guaranteed estimate
println((result.health.status, result.attempts, result.priorEvaluations))
```

All Normal/covariance arguments above are **variances**, not standard deviations.
Run the complete [executable example](../FigaroExamples/src/main/scala/com/cra/figaro/example/documentation/GraphProposalExample.scala):

```sh
sbt "examples / Compile / runMain com.cra.figaro.example.documentation.GraphProposalExample"
```

## Public API reference

The only sampling entry point is `run(config, proposal, logPrior)(model): Result`.

| Parameter | Meaning |
| --- | --- |
| `config: Config` | Fixed attempt, traversal, storage and RNG policy below |
| `proposal: VectorImportance.Proposal` | Frozen normalized joint law, dimension 1–128; finite draws and finite log density at its own draws |
| `logPrior: Vector[Double] => Double` | Pure **original joint prior** log density, finite or negative infinity; not an already-conditioned posterior |
| `model: (Universe, Element[Vector[Double]]) => Element[Double]` | Build owned graph nodes and return one finite scalar query; no sampling, nested algorithm construction or external mutations |

Returns detached `Result` after cleanup. Invalid contracts throw
`IllegalArgumentException`; traversal exhaustion throws `TraversalLimit`; caller
callback exceptions propagate. Interruption is checked around callbacks and in
traversal; the runner uses `InterruptedException`, while called numerical kernels
may themselves throw `CancellationException`. The interrupt flag is not consumed.
Cleanup failures are suppressed onto an existing failure rather than masking it.
No partial estimate is returned after exceptions/cancellation.

`Config(...)` constructs a validated immutable policy (and supports ordinary Scala
case-class `copy`, e.g. `P.Config().copy(draws=2000, maxAttempts=2000)`).

| Field | Default | Contract |
| --- | --- | --- |
| `draws: Int` | 10,000 | Positive requested attempts, **including zero-weight attempts**; at most `health.maxSamples` |
| `maxAttempts: Int` | 10,000 | Positive cap; actual count is `min(draws,maxAttempts)` |
| `maxElementVisits: Long` | 1,000,000 | Positive total observation-lookup cap in graph traversal; not CPU time or number of distinct elements |
| `seed: Long` | 43 | Private scoped sampling stream |
| `randomAlgorithm: SamplingRandom.Algorithm` | Figaro default | Named backend; no auto-selection |
| `maxStoredValues: Long` | 2,000,000 | Positive cap on retained log weights plus scalar values: twice the actual attempt count; not a total heap bound |
| `health: InferenceHealth.Config` | Default policy | Diagnostic-only assessment, never precision stopping |

`Result` is an immutable case class with these read-only fields. Normal application
code obtains it from `run`, not by constructing an unvalidated record manually.

| Field | Meaning / example |
| --- | --- |
| `logWeights: Vector[Double]` | Raw unnormalized weights, including negative infinity; `result.logWeights.size == result.attempts` |
| `values: Vector[Double]` | Matching scalar queries; **zero placeholders on zero-weight attempts**, not raw posterior draws |
| `health: InferenceHealth.ImportanceReport` | Raw-weight/query diagnostics; `result.health.diagnostics.mean` is optional |
| `attempts: Int`, `rejected: Int` | Completed attempts and final negative-infinite weights, including zero evidence/hard rejection |
| `proposalDraws: Long`, `priorEvaluations: Long` | Block draws and original-prior calls; construction-triggered work is also counted if a callback violates the no-sampling guidance |
| `elementVisits: Long` | Actual capped traversal observation lookups, including repeated visits |
| `reason: StopReason` | `DrawsReached` or `MaxAttemptsReached`; not a precision/convergence decision |
| `config: Config`, `randomProvider: String` | Effective policy and backend provenance |

`StopReason` is an enum with the two cases above. `TraversalLimit(limit: Long)` is
the typed exception containing the configured traversal cap; for example,
`catch { case e: P.TraversalLimit => println(e.limit) }` handles a work-budget failure,
not a valid partial estimate. Case-class generated accessors/constructors have the
standard Scala semantics; the [generated reference](api/README.md) links source
signatures as well as inherited Element methods used in examples.

## Three common patterns: old versus new

### 1. Concentrated evidence on a continuous parameter

Standard graph importance builds `Normal(0,1)` as the parameter, observes
`Normal(theta,.25)`, and draws `theta` from its prior on every attempt. With the new
approach, the quick start instead supplies `q=N(.8,.3)`, but **keeps `p=N(0,1)`**
in `logPrior`. Setting `proposal=V.Gaussian(prior)` gives the explicit bridge's
prior-sampling control, with zero root log correction. The likelihood is unchanged.

```scala
val control = P.run(P.Config(seed=43), V.Gaussian(prior), prior.logDensity) { (u,root) =>
  val theta = root.map(_.head)(using "",u)
  Normal(theta,.25)(using "",u).observe(1.0)
  theta
}
// Compare mean error against 0.8 and ESS, not simply the number of draws.
println((control.health.diagnostics.mean, result.health.diagnostics.mean))
```

### 2. Keep a hierarchical layer in the graph

Standard importance samples both `theta` and an additional latent measurement from
their priors. The bridge can improve only `theta` while leaving that layer alone:

```scala
val q = V.Gaussian(G(Vector(1.0/3),Vector(Vector(.8))))
val hierarchical = P.run(P.Config(seed=51),q,prior.logDensity) { (u,root) =>
  val theta = root.map(_.head)(using "",u)
  val latent = Normal(theta,1.0)(using "",u)
  Normal(latent,1.0)(using "",u).observe(1.0)
  theta
}
// Exact posterior mean = 1/3. The remaining latent variable can still limit efficiency.
```

For a correlated multi-parameter root, map each vector coordinate to a node, but
supply its **joint** original prior, not a product of marginal priors that discards
correlations. Improving more coordinates requires explicitly placing them in the
joint block and supplying the corresponding proposal/prior; it is not automatic.

### 3. Fit a multimodal proposal in a discarded graph pilot

Standard prior importance may rarely visit an evidence-favored mode. A single
Gaussian fit may instead waste samples between modes. Run independent graph MCMC
pilot chains, inspect their convergence/mode coverage, fit a bounded mixture, freeze
it with a support-covering defensive component, then build a fresh production graph.
The executable example contains the complete two-mode workflow:

```scala
import com.cra.figaro.algorithm.sampling.GaussianMixtureProposal as M
// pilot is a MultiChainMetropolisHastings.Result with scalar observable "theta".
val traces = pilot.chains.map(_.draws("theta").map(Vector(_)))
val fit = M.fit(traces,M.Config(components=2,diagonalRidge=Vector(1e-4)))
fit.proposal match {
  case None => println(s"No production: ${fit.status}: ${fit.message}")
  case Some(q) =>
    val broad = V.Gaussian(G(Vector(0.0),Vector(Vector(100.0))))
    val frozen = V.Mixture(Vector(.1,.9),Vector(broad,q))
    // Pass the original prior's logDensity, not the pilot's posterior log target.
    // P.run(P.Config(seed=93),frozen,originalPrior.logDensity)(freshGraph)
}
```

The graph MH pilot currently uses explicit log-likelihood constraints rather than
observations; the production graph may use ordinary supported observations. Pilot
draws are unweighted aligned chain traces. Do **not** feed the weighted `values`
from this importance runner into the unweighted fitter. For several observables,
zip coordinates at the same draw index per chain; never shuffle them independently.

The small executable pilot deliberately prints its diagnostics: its recorded run
has R-hat about 1.013, above 1.01. It illustrates plumbing, **not** an approved
converged pilot. Production users must investigate/increase such training or refuse
production under their own policy. A fitted result and a healthy production report
do not establish that the pilot found every mode. Pilot cost and fitting cost are
separate from production counters, and discarded draws cannot be reused as fresh
production observations.

## Gotchas and boundaries

- Never include the same likelihood in both `logPrior` and graph evidence. The
  correction uses the whole mixture density, not the selected component density.
- The root cannot be observed, intervened upon, deactivated or replaced; propagated
  root observations are also rejected. Root conditions/constraints are allowed;
  removing user constraints cannot remove the mandatory prior/proposal correction.
- All dependencies must belong to the supplied Universe. Do not retain its elements,
  mutate another Universe, manually generate samples or construct/start other
  algorithms in the callback. Nested algorithm registration is rejected. Closure
  purity and arbitrary external resources cannot be verified or cleaned by Figaro.
- The runner owns its graph/RNG, not caller callbacks or proposal mutable state.
  For concurrent calls use immutable/thread-safe proposals and pure callbacks.
  Existing graph element classes still have their documented support/limitations;
  this does not make arbitrary shared models thread-safe.
- A draw outside prior support becomes a retained zero-weight attempt before
  downstream parameters are evaluated. Hard conditions also retain zero weight;
  there are **no retries until acceptance**. An impossible model returns no mean.
- Zero-weight query values are placeholders. Only use them with their matching
  weights; an unweighted average, sample fit or ordinary histogram is wrong.
- Work caps do not preempt a callback that never returns, bound model construction,
  count every density callback, or bound all graph/cache allocation. Large models
  need their own resource controls. Exceptions/cancellation produce no partial result.
- Root log correction is stable, but graph likelihoods inherit the numerical and
  observation support of their Element implementations. This is not a universal
  log-density retrofit of legacy distributions.
- Transformed/constrained coordinates need matching prior/proposal Jacobians and
  valid graph parameters. The bridge cannot verify support coverage or coordinates.
- Record the proposal, original prior, graph factory, query, configuration, backend
  provenance and Figaro version for reproducibility. Seed alone is insufficient.
- Health warnings are not calibrated error guarantees. Fixed attempts or explicit
  caps are the only stopping rules; the [calibration findings](IMPORTANCE_CALIBRATION.md)
  remain in force.

## Acceptance evidence

The [complete 600-row study](graph-proposal-results.csv) uses 100 declared seeds,
2,000 attempts per method, and analytic posterior controls. No warning-based
exclusions or retries were used. Both methods use the **same graph bridge**; this
isolates the root proposal choice, not differences in legacy `Importance` scheduling.
Informed proposals are supplied analytic controls, not automatically fitted models.

| Model | Within declared error: prior / informed (of 100) | Median weight ESS: prior / informed | RMSE: prior / informed |
| --- | --- | --- | --- |
| Normal, absolute error ≤ .025 | 98 / 100 | 847 / 1,886 | .01165 / .00872 |
| Hierarchical, absolute error ≤ .05 | 98 / 96 | 1,308 / 1,406 | .02319 / .02484 |
| Two-mode event, absolute error ≤ .025 | 98 / 97 | 1,313 / 1,937 | .01186 / .01083 |

Every row used 2,000 original-prior calls and block draws, with zero rejections in
these fixtures. ESS improvement does not ensure better accuracy in every finite
batch: the hierarchical case did not improve. No wall-clock speedup, calibrated
interval coverage or rare-event guarantee is inferred. The separate
[mixture-fitting study](MIXTURE_PROPOSALS.md) includes pilot costs and harder
separated-mode proposal comparisons.

Nine focused tests cover exact full-density corrections, conjugate and hierarchical
posteriors, mixture/discrete evidence, zero support, impossible evidence, budgets,
cancellation, cleanup, invalid ownership and concurrent replay. An independent
consumer checks this API from the published JAR, not project source. Local package
and CI results are recorded separately when verified.
